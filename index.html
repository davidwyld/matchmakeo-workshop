matchmakEO

  • 📷 Tool for finding earth observation (EO) imagery
  • 🐍 Python package
  • 🗺️ Uses a local geospatial database
  • 👥 Aim to be user-friendly
  • 💬 Looking for feedback at this stage

Documentation 📖 bas-quasar.github.io/matchmakeo

Motivation

  • Aimed specifically at researchers
  • Provide easier access to cross-catalogue metadata analysis
  • Use the power of some technical tools but limit need for understanding

Approach

  • Get metadata from catalogues
  • Put in a geospatial database
  • Write pythonic queries to find the data that you’re looking for

Downloading metadata

from matchmakeo.catalogues import NasaCMR
from matchmakeo.databases import PostGISDatabase
from matchmakeo.download_params import NasaCMRDownloadParams
from matchmakeo import Product

database = PostGISDatabase(
    username="postgres",
    password="password",
    database="matchmakeo",
    host="localhost",
    port=5432,
)

catalogue = NasaCMR(
    client_id="my_name",  # NasaCMR takes a client_id as recommended by CMR
)

download_params = NasaCMRDownloadParams(
    start_date="2020-01-01",
    end_date="2020-01-31",
    lat_max=-70,
    lat_min=-90,
    lon_max=180,
    lon_min=-180,
)

product = Product(
    name="MOD021KM",
    table_name="modis_aqua",
)

catalogue.download_footprints(
    product=product,
    download_params=download_params,
    database=database,
)

Querying

Simple single product queries

from matchmakeo import Product, Query
from matchmakeo.databases import PostGISDatabase

database = PostGISDatabase(
    username="postgres",
    password="password",
    database="matchmakeo",
    host="localhost",
    port=5432,
)

product = Product(
    name="MOD021KM",
    table_name="modis_aqua",
)

results = (
    Query(database, product)
    .intersects_bbox(
        xmin=0.077591,
        ymin=52.169931,
        xmax=0.190887,
        ymax=52.233477,
        srid=4326,
    )
    .execute()
)

Multiple products

results = Query(database, product_a, product_b).intersects_bbox(...).execute()

Features

  • Downloading
    • download a set of metadata without writing API calls yourself
    • with common interface across catalogues,
  • Querying
    • Utilise efficient geospatial database querying to perform more sophisticated queries,
    • Basic queries e.g bbox or polygon intersection, time ranges, metadata parameter value ranges,
    • Cross-product queries including intersections (with thresholds) and time ranges.
  • Visualisation
    • Use common standards so other tools such as QGIS can be used for visualisation

Catalogues

  • cmr.earthdata.nasa.gov
  • earthengine.google.com/
  • JAXA gportal.jaxa.jp/
  • Or, implement your own or request one

Database setup

TL;DR

  • set up a database
    • if admin rights: use docker or postgis or spatialite locally
    • else: use apptainer on workstations
    • or: some other db, e.g. cloud postgis or managed db

Setup instructions

To make the best use of time with the hands-on element of the workshop there are a couple of steps you can do beforehand.

Pre-requisites

  • Some familiarity with python,
  • Access to a geospatial database (see below),
  • Credentials for any metadata catalogues you might want to work with on the day (see below)

Database setup

MatchmakEO requires access to a geospatial database, either PostGIS or Spatialite.

It can be local (on your machine) or accessible in the cloud or on your network, but we don’t yet support database connections over SSH (unless you set up tunnelling or port-forwarding yourself).

Linux/MacOS Users

Following the instructions in the documentation at: https://bas-quasar.github.io/matchmakeo/databases/ set up either a PostGIS or Spatialite database by whichever means you like, it would be interesting to have a spread of different approaches so I won’t recommend a particular one.

If you’re going to work on the workstations, we’d recommend using apptainer (https://bas-quasar.github.io/matchmakeo/databases/#apptainer)

Windows Users

With admin rights

Same as above (but follow windows instructions!)

Without admin rights

If you have a BAS IT managed Windows laptop, you’ll likely have difficulty setting up any of the methods for using a local database if you don’t have admin rights on your machine, so either:

  • use the workstations and apptainer as above,
  • use another database cluster if you have access to one and are confident doing so,
  • possibly create a database in the cloud (note: I haven’t tried this myself) using a service such as:
    • QGIS cloud (https://qgiscloud.com/), or
    • Aiven (https://aiven.io)

Metadata catalogue credentials

MatchmakEO currently supports downloading from three EO metadata catalogues:

  • NASA CMR (Earthdata) - we don’t yet support any functionality that requires credentials, so nothing needed to use this one.
  • Google Earth Engine
  • JAXA G-portal

Therefore, you’ll only need credentials if you want to try using Earth Engine or G-Portal. Follow the instructions in the authentication sections for each catalogue, in the documentation at: https://bas-quasar.github.io/matchmakeo/catalogues/

🐚 Install matchmakEO

  • make a working directory and change directory into it

    mkdir matchmakeo-workshop
cd matchmakeo-workshop

  • make a virtual environment (or use conda/uv/…)

    python -m venv .venv
#or
python3 -m venv .venv

  • activate the virtual environment

    source .venv/bin/activate

  • ensure that your virtual environment is working as expected

    which pip

  • install the matchmakeo package (specify a version)

    pip install git+https://github.com/bas-quasar/matchmakeo.git@v0.0.1

    Note: matchmakEO will be available on pyPI soon!

🐚 Install other dependencies

If using G-portal:

pip install gportal

If using earth engine:

pip install earthengine-api

For running in a notebook:

pip install ipykernel

🐚 Spin up your database

  • Pull the official docker postgis image and convert to an apptainer container definition file
apptainer pull postgis.sif docker://postgis/postgis:18-master
  • Make some directories
mkdir -p ./pg_data ./pg_run
  • Run the container persistently in the background:
apptainer run --cleanenv \
    --env POSTGRES_USER="my_user" \
    --env POSTGRES_PASSWORD="my_secure_password" \
    --env POSTGRES_DB="my_spatial_db" \
    --bind ./pg_data:/var/lib/postgresql \
    --bind ./pg_run:/var/run/postgresql \
    postgis.sif postgres -h 0.0.0.0 -p 5432 \
    > pg.log 2>&1 &

🐍 Run some queries

Construct and execute a simple bounding box query

from matchmakeo import Query

results = (  # use brackets to separate a long query across multiple lines
    Query(database, product)
    .intersects_bbox(
        xmin=0.077591,
        ymin=52.169931,
        xmax=0.190887,
        ymax=52.233477,
        srid=4326,
    )
    .execute()
)

For single products, Query.execute() returns a matchmakeo.ResultSet object which can be used to return the results in a few different formats.

len(results)  # returns the number of results
results.get_ids()  # returns a list of the ids of matching images
results.to_dicts()  # returns a list of dictionaries, each one representing one image and its metadata

🐍 Query multiple products

Simple queries

results = Query(database, product_a, product_b).intersects_bbox(...).execute()

🐍 Join/intersection queries

import datetime

results = (
    Query(database, product_a, product_b)
    .where_spatiotemporal_match(
        product_a,
        product_b,
        relative_to=product_a,  # the product which the overlap fraction is measured against
        min_overlap_fraction=0.1,  # the minimum fraction of the `relative_to` product which is covered by the other product
        max_time_delta=datetime.timedelta(
            days=2
        ),  # the time difference allowed between overlapping pairs
    )
    .execute()
)

# results for more than one product are MatchResultSet objects
# they have the same methods as ResultSet, such as get_ids()
results.get_ids()

# but .to_dicts() returns a list of dicts containing dictionaries each representing a single metadata product
results.to_dicts()

🐍 Chaining queries

results = (
    Query(database, product_a, product_b)
    .intersects_bbox(...)
    .where_spatiotemporal_match(...)
    .execute()
)
